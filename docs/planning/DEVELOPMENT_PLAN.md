# Trip Plan 단계별 개발 계획

문서 버전: 2.3
기준일: 2026-11-12

## 1. 진행 원칙

- 현재 개발 범위는 완료된 2단계와 사용자가 요청한 3단계 홈 환율, 예산·지출 및 권한 기반 준비까지로 제한한다.
- 각 작업은 관련 Unit Test와 필요 시 Room 또는 Compose 계측 테스트를 작성한다.
- 기능 구현 후 관련 테스트를 실행하고, 다음 작업으로 넘어가기 전에 이전 기능을 포함한 전체 회귀 테스트를 실행한다.
- 테스트, Lint 또는 빌드가 실패하면 원인을 수정하고 동일한 검증을 다시 통과시킨다.
- 현재 기능 개발 단계의 기본 검증은 관련 Unit Test, 필요한 Android 계측 테스트, Debug 컴파일·빌드와 Debug Lint로 한다. Release 빌드와 Release Lint Vital은 배포 준비를 시작할 때 다시 검증 항목에 포함한다.
- 최초 공개 배포 전에는 과거 Room 스키마 마이그레이션을 필수 완료 조건으로 두지 않으며, 공개 배포 이후 스키마 변경부터 사용자 데이터 보존을 필수로 검증한다.
- 요청하지 않은 나머지 3단계와 4단계 기능은 현재 코드에 선행 구현하지 않는다.

### 2.3 구현 범위 대조 결과

- 여행 생성 데이터는 Room에 실제 저장된다.
- 여행과 일정의 로컬 Entity, DAO와 Repository 기반은 존재한다.
- 여행 목록은 Room Flow를 관찰하며 최근 생성·수정 순으로 표시하고 날짜·완료 상태를 각 카드에 표시한다.
- 여행 목록에서 상세 Route로 이동하고 여행 기간의 일차 및 날짜별 일정을 조회할 수 있다.
- 일정을 추가, 수정, 삭제하고 다른 날짜로 이동하거나 같은 날짜 안에서 순서를 변경할 수 있다.
- 일정 삭제와 순서 정규화는 Room 트랜잭션으로 처리한다.
- 여행 기본 정보를 수정하고 기간을 변경하거나 여행을 삭제할 수 있다.
- 기간 축소 시 범위 밖 일정 개수를 먼저 알리고, 확인한 경우에만 여행 수정과 일정 삭제를 트랜잭션으로 처리한다.
- 여행 삭제 시 Room 외래키 Cascade로 모든 연관 일정을 함께 삭제한다.
- 버전 1 공유 DTO와 앱 내부 모델을 분리했고 로컬 ID와 기기 정보를 파일에서 제외했다.
- JSON 파일 내보내기, 가져오기 전 검증·미리보기와 새 여행 트랜잭션 저장을 구현했다.
- Storage Access Framework 저장·선택, FileProvider 공유와 외부 `ACTION_VIEW` 파일 열기를 연결했다.
- 같은 파일을 여러 번 가져오면 기존 여행을 덮어쓰지 않고 각각 새 로컬 ID를 가진 여행으로 추가한다.
- 일정 저장 중 강제 오류가 발생해도 가져온 여행과 선행 일정이 모두 롤백된다.
- 500개 일정, 윤년 날짜 경계와 여행 범위 밖 일정 거부를 검증했다.
- Room 1→3 및 2→3 마이그레이션과 DB 재개방 후 여행·일정·순서 유지를 검증했다.
- 2단계 Room v4 기반과 1→4·2→4·3→4 마이그레이션, 준비물 Cascade 및 장소 참조 `SET NULL`을 검증했다.
- 날짜 기반 여행 상태와 사용자 완료 상태를 분리하고, 완료·완료 취소 시각을 Room에 저장하도록 구현했다.
- 완료한 여행을 현재·미래 날짜로 변경할 때 완료 해제 확인을 요구하고, 확인 전 데이터가 변경되지 않도록 구현했다.
- Room 재개방 후에도 완료 상태가 유지되는 것을 실제 기기에서 검증했다.
- 로컬 지역 검색은 오프라인 보조 기능으로 이미 구현되어 있으나 여행에는 목적지 문자열만 저장한다.
- 3단계 범위였던 미사용 예산 포맷 코드와 Presentation의 중복 날짜 계산 로직은 제거했다.

## 4. 1단계 완료 조건

- 네트워크 없이 여행을 생성하고 다시 조회할 수 있다.
- 날짜별 일정을 추가, 수정, 삭제하고 순서를 변경할 수 있다.
- 앱 재실행 후 여행, 일정과 순서가 유지된다.
- 여행 계획을 하나의 파일로 내보낼 수 있다.
- 다른 기기에서 파일을 가져오면 동일한 여행 구조가 생성된다.
- 오류나 손상 파일 때문에 기존 로컬 데이터가 손실되지 않는다.
- 전체 테스트, Lint와 빌드가 통과한다.
