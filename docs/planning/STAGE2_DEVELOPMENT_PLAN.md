# Trip Plan 2단계 개발 계획

문서 버전: 1.1
기준일: 2026-11-10
상태: 1~14일 차 완료

현재 검증 기준:

- Unit Test 101개 성공, 실패 0개
- 실제 연결 기기 Android 계측 테스트 50개 성공, 실패 0개
- Android Lint 성공
- Debug APK 빌드 성공
- Release APK 빌드와 Release Lint Vital 성공
- 현재 Room v4 저장·재개방 검증 성공
- 실제 기기 공유 파일 v1·v2 왕복, 설치와 Cold Start 성공

버전 표기 구분:

- `Room 1→4`, `2→4`, `3→4`는 앱 내부 데이터베이스 스키마 마이그레이션을 뜻한다.
- `공유 파일 v1·v2`는 친구에게 전달하는 JSON 파일 포맷 버전을 뜻한다.
- Room 스키마 버전과 공유 파일 포맷 버전은 서로 독립적으로 관리한다.

## 1. 목표

2단계는 1단계의 오프라인 여행 계획과 파일 공유를 유지하면서 여행 상태, 준비물, 여행 복사와 재사용 장소 기능을 확장한다.

- D-Day, 여행 중 일차, 여행 종료와 사용자 완료 상태
- 공통·개인 준비물 체크리스트
- 일정 포함 여부와 일차 제거를 지원하는 여행 복사
- 공급자 중립적인 구조화 장소와 오프라인 직접 입력
- 공통 준비물과 구조화 장소를 포함하는 공유 파일 v2
- 최근 수정 순 여행 목록
- 설정 메뉴와 진입 화면

## 2. 개발 원칙

- 핵심 기능은 서버, 로그인과 네트워크 없이 동작한다.
- Google Places와 지도 SDK 실제 연동은 이번 일정에 포함하지 않는다.
- Room 스키마, Domain 모델과 공유 DTO를 서로 분리한다.
- 2단계의 Room 스키마 변경은 가능한 한 하나의 버전 4 마이그레이션으로 설계한다.
- 공유 파일 v2를 내보내되 v1과 v2를 모두 가져올 수 있어야 한다.
- 기능 구현과 Unit Test, Room Test, ViewModel Test 및 Compose Preview를 함께 진행한다.
- 각 일차의 관련 테스트가 통과한 후 누적 회귀 테스트를 실행하고 다음 일차로 넘어간다.
- 실패가 발생하면 원인을 수정하고 같은 검증을 다시 통과시킨다.

## 4. 구현 전 기술 기준

### 여행 상태

- 날짜 상태는 저장하지 않고 시작일·종료일과 `Clock`으로 계산한다.
- 사용자 완료 시각만 nullable 값으로 Room에 저장한다.
- 완료 상태는 공유하거나 여행 복사에 포함하지 않는다.

### 준비물

- 공통과 개인 유형은 생성 시 확정하고 변경하지 않는다.
- 공통 항목의 내용만 공유하며 체크 상태와 완료 시각은 공유하지 않는다.
- 개인 준비물은 어떤 공유 파일에도 포함하지 않는다.
- 체크 상태는 기기별로 독립적으로 관리한다.

### 여행 복사

- 팝업에서 새 이름, 새 날짜 범위와 일정 포함 여부를 확인한다.
- 원본 일차가 더 많으면 모든 일차를 보여주고 초과 수만큼 복사 대상에서 제거한다.
- 남은 일차는 원본 표시 순서대로 새 여행 1일차부터 배치한다.
- 원본 데이터는 변경하지 않고 복사본 전체를 하나의 트랜잭션으로 저장한다.
- 2단계 첫 버전에서는 준비물을 여행 복사 대상에 포함하지 않는다. 준비물 복사는 실제 사용 후 별도 옵션으로 검토한다.

### 장소

- 직접 입력 장소는 이름만으로 저장할 수 있고 주소와 좌표는 선택 값이다.
- 일정은 nullable 장소 참조와 장소 이름 사본을 함께 가진다.
- 장소 삭제 후에도 일정의 이름 사본은 유지한다.
- 외부 공급자 타입은 앱 자체 enum 또는 값 객체를 사용하고 Google SDK 타입을 노출하지 않는다.

### 목록

- 상태별 섹션과 검색·필터 대신 하나의 최근 순 목록을 사용한다.
- `updatedAt` 내림차순으로 표시하고 각 카드에서 날짜·완료 상태를 보여준다.
