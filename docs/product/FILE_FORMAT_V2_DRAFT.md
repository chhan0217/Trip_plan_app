# Trip Plan 공유 파일 형식 v2 계약

문서 버전: 1.0
기준일: 2026-11-10
상태: 구현 및 실제 기기 왕복 검증 완료

## 목적

공유 파일 v2는 v1의 여행·일정 구조에 공통 준비물과 선택적 구조화 장소를 추가한다. 앱은 v2로 내보내고 v1과 v2를 모두 가져온다.

## 호환성

- `formatVersion`은 `2`다.
- 새 앱은 v1과 v2를 모두 가져올 수 있어야 한다.
- v1 장소 문자열은 자유 입력 장소로 가져온다.
- v1 파일에는 준비물이 없으므로 빈 준비물 목록으로 처리한다.
- v2 파일을 지원하지 않는 기존 앱은 임의 변환하지 않고 미지원 버전 오류를 표시한다.

## JSON 계약

```json
{
  "formatVersion": 2,
  "trip": {
    "title": "제주 여행",
    "destination": "제주",
    "startDate": "2026-11-09",
    "endDate": "2026-11-11",
    "description": "친구와 여행"
  },
  "itineraryItems": [
    {
      "date": "2026-11-09",
      "title": "제주공항 도착",
      "place": "제주국제공항",
      "placeDetails": {
        "address": "제주시 공항로 2",
        "latitude": 33.5104,
        "longitude": 126.4914
      },
      "startTime": "09:00",
      "endTime": "10:00",
      "note": "",
      "order": 0
    }
  ],
  "sharedPackingItems": [
    {
      "name": "여권",
      "category": "서류",
      "quantity": 1,
      "memo": "유효기간 확인",
      "order": 0
    }
  ]
}
```

## 장소 규칙

- `place` 문자열은 일정 표시 사본으로 유지한다.
- `placeDetails`는 구조화 장소를 선택한 경우에만 포함할 수 있다.
- 주소는 빈 문자열을 허용하고 위도·경도는 둘 다 있거나 둘 다 없어야 한다.
- Room `placeId`, 외부 SDK 객체와 기기 전용 경로는 포함하지 않는다.
- 외부 공급자 식별자의 파일 포함 여부는 실제 Google 연동 시 별도로 확정한다.

## 준비물 규칙

- `Shared` 공통 준비물만 `sharedPackingItems`에 포함한다.
- `Personal` 개인 준비물은 포함하지 않는다.
- 체크 여부와 완료 시각은 포함하지 않는다.
- 가져온 공통 준비물은 모두 미완료 상태와 새 로컬 ID로 생성한다.
- 이름, 카테고리, 수량, 메모와 표시 순서를 전달한다.

## 공유하지 않는 값

- 여행, 일정, 장소와 준비물의 Room ID
- 여행 완료 상태와 완료 시각
- 준비물 체크 상태와 완료 시각
- 개인 준비물
- 캐시 경로, 파일 경로와 UI 상태
- Google SDK 타입과 내부 응답 객체

## 고정 및 왕복 테스트

- `formatVersion`이 항상 JSON에 존재하는지
- 개인 준비물과 체크·완료 상태가 직렬화 모델에 없는지
- 로컬 여행·일정·장소 ID가 없는지
- v1과 v2 Decoder가 명확히 분기되는지
- v2 왕복 후 여행·일정·공통 준비물·장소 사본이 보존되는지

2026-11-10 실제 기기 계측 테스트에서 v1 가져오기와 v2 내보내기·가져오기 왕복, 개인 준비물 및 체크·완료 상태 제외를 다시 검증했다.
