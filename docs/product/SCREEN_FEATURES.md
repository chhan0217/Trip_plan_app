# Trip Plan 화면별 기능 안내

문서 버전: 2.2
기준일: 2026-11-10
상태: 2단계 완료, 3단계 홈 환율 조회 구현

## 1. 문서 목적

이 문서는 현재 앱에 구현된 화면별 기능과 화면 이동, 입력 규칙, 오류 처리를 설명한다. 사용자 관점의 동작을 기준으로 하며 개발 시 화면 동작을 확인하는 기준 문서로도 사용한다.

## 2. 전체 화면 구성

| 화면 | 주요 목적 | 진입 경로 |
|---|---|---|
| 여행 목록 | 오늘의 환율과 최근 수정 순 여행 조회, 새 여행 시작, 파일 가져오기, 설정 진입 | 앱 실행 |
| 새 여행 만들기 | 여행 기본 정보 생성 | 여행 목록 → 새 여행 추가 |
| 여행 상세 | 일차별 일정 조회 및 여행 관련 기능 진입 | 여행 목록 → 여행 선택 |
| 일정 추가·수정 | 일정 생성, 편집, 삭제 | 여행 상세 → 일정 추가 또는 기존 일정 선택 |
| 여행 수정 | 여행 정보와 기간 수정, 여행 삭제 | 여행 상세 → 여행 수정 |
| 준비물 | 공통·개인 준비물 생성, 수정, 삭제와 체크 | 여행 상세 → 준비물 |
| 여행 복사 | 새 기간과 포함 일차를 선택해 여행 복사 | 여행 상세 → 여행 복사 |
| 저장된 장소 | 직접 입력 장소 생성, 수정과 삭제 | 여행 상세 → 장소 |
| 설정 | 현재 저장 방식 안내와 향후 설정 진입점 | 여행 목록 → 설정 |
| 여행 파일 공유 | 여행을 JSON 파일로 저장하거나 다른 앱에 공유 | 여행 상세 → 파일 공유 |
| 여행 파일 가져오기 | 공유 파일 검증, 미리보기, 새 여행 저장 | 여행 목록 → 여행 파일 가져오기 또는 외부 파일 열기 |

## 3. 기본 사용자 흐름

### 3.1 직접 여행 만들기

1. 여행 목록에서 `새 여행 추가`를 선택한다.
2. 여행 이름과 날짜를 입력하고 여행을 만든다.
3. 생성된 여행을 목록에서 선택해 상세 화면으로 이동한다.
4. 일차를 선택하고 일정을 추가한다.
5. 필요하면 여행이나 일정을 수정한다.

### 3.2 친구에게 여행 전달하기

1. 여행 상세에서 `파일 공유`를 선택한다.
2. `친구에게 공유` 또는 `기기에 파일 저장`을 선택한다.
3. 친구는 전달받은 `.tripplan.json` 파일을 앱으로 연다.
4. 파일 미리보기 내용을 확인하고 `새 여행으로 가져오기`를 선택한다.
5. 가져온 여행 상세 화면에서 원본과 같은 날짜 및 일정 구조를 확인한다.

파일은 특정 시점의 계획 사본이다. 가져온 뒤 각 사용자가 수정한 내용은 서로 자동 동기화되지 않는다.

## 4. 여행 목록 화면

### 표시 정보

- 여행을 `updatedAt` 내림차순의 하나의 최근 목록으로 표시한다.
- 여행 카드에는 여행 이름, 시작일·종료일, 목적지와 날짜 상태를 표시한다.
- 날짜 상태는 오늘을 기준으로 D-Day, 여행 중 일차 또는 여행 종료로 계산한다.
- 사용자가 완료한 여행은 날짜 상태와 별도로 완료 상태를 표시한다.
- 여행이 없으면 새 여행 생성과 파일 가져오기를 안내하는 빈 상태를 표시한다.
- `오늘의 환율` 카드에는 선택한 통화의 원화 매매 기준율과 실제 환율 기준일을 표시한다.
- 최초 기본 통화는 미국 달러, 일본 엔, 유로이며 베트남 동을 포함한 지원 통화 중 표시 대상을 바꿀 수 있다.
- 환율은 `1 USD`, `100 JPY`, `1,000 VND`처럼 통화별 읽기 좋은 단위로 표시한다.
- 표시 금액은 반올림해 소수점 첫째 자리까지 보여준다.

### 사용자 동작

- `새 여행 추가`: 새 여행 만들기 화면으로 이동한다.
- `여행 파일 가져오기`: Android 문서 선택기를 열어 JSON 여행 파일을 선택한다.
- `통화 선택`: 조회된 통화 목록에서 홈에 표시할 통화를 하나 이상 선택한다.
- `새로고침`: 최신 환율을 다시 요청한다.
- 여행 카드 선택: 해당 여행의 상세 화면으로 이동한다.

### 상태 및 오류

- 데이터를 읽는 동안 로딩 표시를 보여준다.
- Room 데이터 조회에 실패하면 앱을 다시 실행하도록 안내한다.
- 목록은 Room의 변경을 관찰하므로 여행 생성·수정·삭제 결과가 자동 반영된다.
- 앱 실행 시 Room에 마지막으로 저장한 정상 환율을 먼저 보여주고 최신 환율을 백그라운드에서 요청한다.
- 주말·휴일의 빈 응답은 최대 7일 전까지 직전 기준일을 조회하며, 네트워크 실패 시 기존 캐시를 유지한다.
- 선택 통화는 DataStore에 저장되어 다음 앱 실행에도 유지된다.
- 환율 조회에 실패하면 안내 문구를 표시하며 여행 목록 사용은 막지 않는다.

## 5. 새 여행 만들기 화면

### 입력 항목

| 항목 | 필수 여부 | 규칙 |
|---|---|---|
| 여행 이름 | 필수 | 공백만 입력할 수 없음 |
| 여행 지역 | 선택 | 두 글자 이상 입력하면 기기 내 지역 데이터에서 검색 |
| 여행 날짜 | 필수 | 시작일과 종료일을 범위로 선택하며 종료일은 시작일보다 빠를 수 없음 |
| 여행 메모 | 선택 | 여행 설명이나 준비 메모 입력 |

지역 검색은 로컬 데이터로 동작하므로 네트워크가 없어도 사용할 수 있다. 검색 결과를 선택하지 않고 사용자가 직접 목적지를 입력하는 것도 가능하다.

### 사용자 동작

- 날짜 영역 선택: 날짜 범위 선택창을 연다.
- `여행 만들기`: 입력값을 검증한 뒤 Room에 여행을 저장한다.
- 뒤로가기: 저장하지 않고 여행 목록으로 돌아간다.

### 상태 및 오류

- 여행 이름이나 날짜가 잘못되면 해당 입력란에 오류를 표시한다.
- 저장 중에는 중복 저장을 막고 진행 상태를 표시한다.
- 저장 실패 시 다시 시도할 수 있는 오류 메시지를 표시한다.
- 저장 성공 시 여행 목록으로 돌아간다.

## 6. 여행 상세 화면

### 표시 정보

- 여행 이름, 목적지, 여행 기간과 메모를 표시한다.
- 여행 기간을 `1일차`, `2일차`와 같은 일차 탭으로 자동 계산한다.
- 선택한 날짜에 속한 일정만 카드 목록으로 표시한다.
- 일정 카드에는 시간, 제목, 장소와 메모를 표시한다.
- 선택한 날짜에 일정이 없으면 빈 일정 메시지를 표시한다.

### 사용자 동작

- 일차 탭 선택: 해당 날짜의 일정 목록으로 전환한다.
- `일정 추가`: 현재 선택한 날짜가 지정된 일정 추가 화면으로 이동한다.
- 일정 카드 선택: 해당 일정 수정 화면으로 이동한다.
- `위로`·`아래로`: 시작 시간이 같은 일정끼리 사용자 순서를 변경한다.
- `여행 수정`: 여행 수정 화면으로 이동한다.
- `파일 공유`: 여행 파일 공유 화면으로 이동한다.
- `준비물`: 공통·개인 준비물 화면으로 이동한다.
- `여행 복사`: 새 날짜 범위로 여행을 복사하는 화면으로 이동한다.
- `장소`: 저장된 장소 관리 화면으로 이동한다.
- `여행 완료`·`완료 취소`: 확인 후 로컬 완료 상태를 변경한다.

일정은 기본적으로 시작 시간이 빠른 순서로 자동 정렬된다. 시작 시간이 없는 일정은 시간이 있는 일정 뒤에 표시되며, 같은 시작 시간 안에서만 수동 순서를 변경할 수 있다.

### 상태 및 오류

- 여행 또는 일정 조회 중에는 로딩 상태를 표시한다.
- 삭제되었거나 존재하지 않는 여행이면 찾을 수 없다는 메시지를 표시한다.
- 일정 순서 변경에 실패하면 현재 화면에 오류 메시지를 표시한다.

## 7. 일정 추가·수정 화면

일정 추가와 수정은 같은 화면을 사용한다. 기존 일정 ID가 있으면 수정 모드, 없으면 추가 모드로 동작한다.

### 입력 항목

| 항목 | 필수 여부 | 규칙 |
|---|---|---|
| 일차·날짜 | 필수 | 여행 기간 안의 날짜만 선택 가능 |
| 일정 제목 | 필수 | 공백만 입력할 수 없음 |
| 장소 | 선택 | 자유 입력 문자열 |
| 시작 시간 | 선택 | `HH:mm` 형식 |
| 종료 시간 | 선택 | `HH:mm` 형식이며 시작 시간보다 빠를 수 없음 |
| 메모 | 선택 | 일정 관련 메모 |

### 사용자 동작

- 일차 선택: 일정을 다른 여행 날짜로 이동하거나 새 일정 날짜를 지정한다.
- `일정 추가` 또는 `일정 저장`: 입력값을 검증하고 저장한다.
- `일정 삭제`: 수정 모드에서만 표시되며 확인창을 거쳐 삭제한다.
- 뒤로가기: 저장하지 않고 여행 상세로 돌아간다.

### 저장 후 정렬

- 시작 시간이 빠른 일정부터 자동 정렬한다.
- 시작 시간이 없는 일정은 뒤로 이동한다.
- 동일한 시간의 일정은 기존 사용자 순서를 최대한 유지한다.
- 삭제 후 남은 일정의 순서는 0부터 다시 정규화한다.

### 상태 및 오류

- 제목 누락, 시간 형식 오류와 종료 시간이 더 빠른 경우를 표시한다.
- 여행 기간 밖의 날짜는 저장하지 않는다.
- 저장·삭제 실패 시 현재 입력을 유지하고 오류 메시지를 표시한다.
- 저장 또는 삭제 성공 시 여행 상세 화면으로 돌아간다.

## 8. 여행 수정 화면

### 수정 가능한 항목

- 여행 이름
- 여행 지역
- 시작일과 종료일
- 여행 메모

입력 규칙은 새 여행 만들기와 동일하다.

### 기간 변경 보호

- 여행 기간을 줄여 기존 일정이 새 기간 밖으로 나가면 즉시 삭제하지 않는다.
- 삭제 대상 일정 개수를 확인창에 표시한다.
- 사용자가 `삭제 후 변경`을 선택한 경우에만 여행 기간 변경과 범위 밖 일정 삭제를 하나의 트랜잭션으로 처리한다.
- 취소하면 기존 여행과 일정을 유지한다.

### 여행 삭제

- `여행 삭제`를 선택하면 복구할 수 없다는 확인창을 표시한다.
- 확인하면 여행과 모든 연관 일정을 함께 삭제한다.
- 삭제 성공 시 내비게이션 기록을 정리하고 여행 목록으로 이동한다.

### 상태 및 오류

- 여행을 찾을 수 없는 상태와 조회 실패 상태를 구분한다.
- 저장·삭제 중에는 중복 동작을 막는다.
- 처리 실패 시 다시 시도할 수 있도록 현재 화면을 유지한다.

## 9. 여행 파일 공유 화면

### 표시 정보

- 생성될 `.tripplan.json` 파일 이름을 표시한다.
- 공유 파일에 여행·일정·공통 준비물·구조화 장소 사본만 포함되고 계정이나 기기 정보는 포함되지 않는다고 안내한다.

### 사용자 동작

- `친구에게 공유`: 앱 캐시에 공유 파일을 만들고 Android 공유 시트를 연다.
- `기기에 파일 저장`: Android 문서 생성 화면을 열어 사용자가 선택한 위치에 저장한다.

### 파일 내용

- 파일 포맷 버전
- 여행 이름, 목적지, 기간과 메모
- 일정 날짜, 제목, 장소, 시간, 메모와 순서
- 공통 준비물의 이름, 카테고리, 수량, 메모와 순서
- 구조화 장소의 이름, 주소와 선택적 좌표

Room ID, 개인 준비물, 체크·완료 상태, 캐시 경로, 기기 경로, 생성 시각과 UI 상태는 파일에 포함하지 않는다.

### 상태 및 오류

- 파일 생성·저장 중에는 버튼을 비활성화하고 진행 상태를 표시한다.
- 저장 성공 메시지와 파일 생성·쓰기 실패 메시지를 구분해 표시한다.
- 새 내보내기는 [공유 파일 형식 v2](FILE_FORMAT_V2_DRAFT.md)를 따르며 기존 v1 파일 가져오기도 지원한다.

## 10. 여행 파일 가져오기 화면

### 진입 방법

- 여행 목록의 `여행 파일 가져오기`에서 파일을 선택한다.
- 파일 앱이나 메신저에서 JSON 파일을 Trip Plan 앱으로 연다.

### 저장 전 검증

- JSON 문법과 공유 파일 구조
- `formatVersion` 지원 여부
- 여행 제목과 날짜 범위
- 각 일정 날짜가 여행 기간 안에 있는지 여부
- 일정 제목, 시간 형식과 순서 값

검증을 통과하기 전에는 Room 데이터를 변경하지 않는다.

### 미리보기 정보

- 여행 이름과 목적지
- 시작일과 종료일
- 전체 여행 일수
- 일정 개수

### 사용자 동작

- `새 여행으로 가져오기`: 기존 여행을 수정하지 않고 새 로컬 ID를 가진 여행과 일정을 저장한다.
- 뒤로가기: 아무 데이터도 저장하지 않고 이전 화면으로 돌아간다.

가져오기 성공 시 새로 생성된 여행의 상세 화면으로 이동한다. 같은 파일을 다시 가져오면 기존 여행을 덮어쓰지 않고 별도의 여행으로 추가한다.

### 오류 안내

| 오류 | 사용자 안내 |
|---|---|
| 파일 읽기 실패 | 파일을 읽지 못했습니다. |
| JSON 또는 구조 오류 | 여행 계획 파일 형식이 아닙니다. |
| 미지원 버전 | 현재 앱에서 지원하지 않는 파일 버전입니다. |
| 날짜·일정 데이터 오류 | 파일의 여행 또는 일정 정보가 올바르지 않습니다. |

가져오기 저장은 하나의 Room 트랜잭션으로 처리한다. 일정 하나라도 저장에 실패하면 새 여행과 앞서 저장된 일정까지 모두 롤백하며 기존 로컬 여행은 변경하지 않는다.

## 11. 2단계 추가 화면

### 준비물

- 공통 준비물과 내 준비물을 구분해 표시한다.
- 항목을 추가·수정·삭제·체크할 수 있으며 생성 후 유형은 변경할 수 없다.
- 공통 준비물만 공유 파일에 포함하고 개인 준비물과 체크 상태는 기기에만 남긴다.

### 여행 복사

- 새 여행 이름과 날짜 범위, 일정 포함 여부를 입력한다.
- 원본 전체 일차에서 가져올 일차를 선택하고 포함·제외 일정 개수를 확인한다.
- 최종 확인 후 새 여행과 일정을 트랜잭션으로 저장하며 원본은 변경하지 않는다.

### 저장된 장소

- 네트워크 없이 장소 이름과 선택적 주소를 생성·수정·삭제한다.
- 일정 편집 화면에서 저장된 장소를 선택하거나 자유 입력 장소를 사용할 수 있다.
- 저장 장소를 삭제해도 기존 일정의 장소 이름 사본은 유지된다.

### 설정

- 여행 데이터가 기기에 저장되고 파일로 공유된다는 안내를 표시한다.
- 실제 설정값이 없으므로 DataStore나 동작하지 않는 설정 스위치는 제공하지 않는다.

## 12. 화면 이동 규칙

- 일반적인 뒤로가기는 직전 화면으로 돌아간다.
- 여행 생성, 여행 수정과 일정 저장 성공 시 직전 화면으로 돌아간다.
- 여행 삭제 성공 시 여행 목록을 새로운 기준 화면으로 만든다.
- 파일 가져오기 성공 시 가져오기 화면을 제거하고 새 여행 상세로 이동한다.
- 외부 파일로 앱을 실행해도 먼저 가져오기 미리보기를 보여주며 자동 저장하지 않는다.

## 13. 공통 기술 및 검증 기준

- 모든 화면은 ViewModel의 단일 `StateFlow` UI 상태를 관찰한다.
- 화면은 Repository, DAO와 파일 시스템을 직접 호출하지 않고 UseCase를 통해 동작한다.
- 저장 성공, 삭제 성공과 공유 실행 같은 일회성 동작은 UI 상태와 별도 이벤트로 처리한다.
- 각 Compose 화면에는 기본·데이터·오류 상태를 확인할 Preview가 있다.
- 화면과 ViewModel 동작은 Unit Test 및 실제 기기 Compose 계측 테스트로 검증한다.
- 핵심 여행 기능은 네트워크, 계정, 로그인과 서버 없이 동작한다.

## 14. 현재 화면 범위에서 제외된 기능

- 로그인과 계정 화면
- 서버 동기화 및 실시간 공동 편집
- 지도와 온라인 장소 검색
- 채팅과 친구 목록
- 예산, 사진과 여행 일지
- 서로 다른 여행 파일의 자동 병합 또는 덮어쓰기

이 기능들은 현재 2단계 화면에 포함하지 않으며 후속 단계 요구사항 확정 후 별도로 설계한다.
